# Application error codes

**Clients** see short plain-language messages (e.g. “Login failed”, “Failed to upload report”).
**Servers / support** use numeric codes for diagnosis — in API logs (`[api] ERROR {code} — {key}`) and in the JSON payload `error.code` (not rendered in the UI).

API responses use:

```json
{
  "error": {
    "code": 150,
    "key": "OPCO_NOT_FOUND",
    "message": "OPCO NOT FOUND"
  }
}
```

HTTP status remains separate for protocol. Source of truth: [`lib/errors/catalog.ts`](../lib/errors/catalog.ts).

## Number ranges (3-digit)

| Range | Domain |
|-------|--------|
| 100–119 | Auth / session |
| 120–149 | Common validation / access |
| 150–179 | Admin organization (OpCo / Partner) |
| 180–199 | Users |
| 200–249 | Currencies / rates / settings |
| 250–319 | Reports / upload / storage |
| 320–359 | Invoices |
| 360–399 | Reconciliation / consolidation |
| 400–449 | Notifications / reminders |
| 900–909 | System / unexpected |
